# 报告模板

中档与高档按此结构输出；低档保留相同标题，但每节压缩到几行。标题用对话语言。

```markdown
# <问题一句话>（<档位>）

## 一、第一性原理
**已确认的事实**
- 【事实】……（来源：用户 / 代码 <路径> / 链接）
**未经验证的假设**
- ……  —— 如何验证：……；若不成立会影响：……
**真正目标**：……（字面目标与上追一层的目标不同时两个都写）
**现实约束**：时间 / 预算 / 人力 / 技术 / 组织 / 合规 ……
**重新定义的问题**：……
**可能路径**：A …… / B …… / C 不做或换问题 ……

## 二、现实案例检索
| 案例 | 做法 | 结果 | 原因 | 条件差异 | 来源 |
|---|---|---|---|---|---|
（成功与失败都列；凭记忆的标【记忆，未核实】；没找到失败案例就写出来）

**反复出现的教训**：……
**可迁移**：…… **不能照搬**：……（因为哪个条件不同）

## 三、跨领域借解
**底层结构**：……  **核心矛盾**：……

### <领域/历史案例>
1. 原问题：……
2. 结构相似：<我方变量> ↔ <对方变量> ……
3. 解决机制：……
4. 可迁移：……
5. 不能照搬：机制中 <哪一环> 会断，因为 ……
（数量按问题需要；弱类比明确标注）

## 四、专家会诊
### 4.1 独立判断
| | 视角 A | 视角 B | 视角 C（列数按所选视角数） |
|---|---|---|---|
| 怎样定义问题 | | | |
| 最推荐路径 | | | |
| 其他视角易忽略 | | | |
| 改变判断的证据 | | | |

### 4.2 交叉质疑
- A 质疑 B：……  B 回应：……（各方都要挨质疑）
- **共同认可的事实**：……
- **真正的分歧**：……
- **分歧背后的假设**：……
- **最值得优先验证的关键假设**：……

## 五、综合结论
| 项目 | 结论 |
|---|---|
| 1. 问题本质 | 真正需要解决的核心矛盾 |
| 2. 现实经验 | 成功与失败案例的关键教训 |
| 3. 最推荐的方案 | |
| 4. 比较优势 | 为什么优于主要替代方案（点名替代方案） |
| 5. 适用条件 | 什么前提和约束下成立 |
| 6. 最大风险 | 最可能导致失败的因素 |
| 7. 停止条件 | 可观测的信号：指标 / 时间点 / 事件 |
| 8. 第一步实验 | 验证哪个假设、怎么做、多久、通过标准、失败后转向哪里 |

## 附：未验证的关键假设（仅在存在会影响结论的假设时写）
- 假设：……；若不成立，结论改为：……
```

高档额外在报告末尾附：

```markdown
## 附录 A：证据台账
| # | 判断 | 标签 | 来源 | 来源等级（一手/讨论/媒体/营销） |

## 附录 B：红队反驳
- 最强反驳：……
- 回应 / 未能回应的部分：……
- 因此对结论的修正：……
```
