# 轻量档 · 7 字段 /goal 指令

一条普通 prompt 告诉 agent 现在做什么;一条 goal 定义一份持久的作业契约:什么结果算数、怎么证明完成、什么不能变、可以在哪动手、失败后怎么迭代、何时停止、何时暂停等人。

**值得用 /goal 的**:编码/调试/重构/发布、要验证的 UI 或产品改动、多步调研或文档生产、仓库清理/迁移/打包——一切「完成」必须用命令、产物、截图、日志或外部状态证明的活。
**不值得的**:一句话能答的、简单改写翻译、一条 shell 就出结果的。直说不用 goal。

## 模板(中文,默认)

```text
/goal [目标结果——干完世界什么样,不是「去做 X」]。
验证:[命令 / 产物 / 截图 / 日志 / 外部证据]。
约束:[不能改变的行为、接口、数据、风格或分支规则]。
边界:[允许写入的位置 / 禁止触碰的路径或系统]。
迭代策略:[一次一个聚焦改动,重跑检查,基于日志调整,最多 N 轮]。
完成条件:[哪些证据证明可以停止]。
暂停条件:[需要人工决定、凭证、外部权限、预算或破坏性操作的情况]。
```

命令前缀永远是 `/goal`,不是 `/目标`。轻量档代码块自带前缀,领导整块复制直接发送,不再另输 `/goal`。英文镜像(点名才给)字段名换为 Verification / Constraints / Boundaries / Iteration policy / Stop when / Pause if,语义必须与中文版一致——一份扩大范围一份缩小范围,是事故。

## 七要素各自回答什么

| 要素 | 回答的问题 | 好内容 |
|---|---|---|
| 目标结果 | 最后要变成什么状态? | 用户可见或仓库可见的结果 |
| 验证 | 怎么证明完成? | 命令、测试、构建、截图、日志、API 检查、文件 |
| 约束 | 什么不能变? | 行为、公开 API、数据结构、风格、密钥、分支规则 |
| 边界 | 可以写哪里? | 允许目录白名单、禁止路径、不做无关重构 |
| 迭代策略 | 失败后怎么继续? | 小步改动、重跑检查、先读日志再换策略、轮数上限 |
| 完成条件 | 什么时候停? | 证据,不是感觉 |
| 暂停条件 | 什么时候等人? | 凭证、付费、生产数据、破坏性选择、方向裁决、预算上限 |

## 起草规则

- 验证优先写项目自己暴露的命令(package scripts、Makefile、CI 配置、Xcode schemes);现有项目查不到就把「先找出项目的检查命令」写进目标,别发明;新建项目还没有脚本——跳过,验证写「启动本地应用走通核心流程,截图/日志为证」。
- 命令不够证明时补产物:改动文件清单、截图、导出 PDF、发布 URL、PR、日志、API 响应。
- 「什么不能变」归约束,文件系统权限归边界,别混。
- 迭代策略里写死:同一错误连败 2 次必须换证据来源;禁止「keep trying」「直到满意」。
- **从完整档借来的加固**:验证含测试时,约束里点名反作弊姿势(不许 skip/放宽断言/mock 被测对象/删测试/`|| true`,测试数与覆盖率只许 ≥ 现状);某项检查「坏了也没人知道」时,验证里加反向验证——故意弄坏一次,贴变红输出,还原贴全绿。

## 输出形状(任务还模糊时)

1. `推荐执行版(中文,可直接复制)`:最优默认拼好的完整 /goal——第一块必须能跑,不放半填模板,领导常常直接复制第一块。
2. `默认选择理由`:一句。
3. `可选调整`:编号选择题带推荐默认(题库见 defaults-and-risk.md)。
4. `你可以直接回复`:「按默认」或「1B 2A 3C」。

领导答完选择题,只回一句用法加一块 `最终可复制 /goal`,不重复解释、不再附可选调整。

## 强例(修 bug)

```text
/goal 修复结算折扣 bug:百分比券每单只生效一次,固定面额券仍可与礼品卡叠加。
验证:跑仓库的 checkout 单测;为百分比券补一条回归测试;跑 package scripts 里最小的 lint/typecheck。
约束:不改优惠券公开 API 名、数据库 schema、礼品卡行为和无关结算文案;不许 skip/放宽断言/删测试,测试数只许 ≥ 现状。
边界:只改结算定价逻辑、优惠券测试与直接相关 fixtures;不碰支付商配置和 migration 文件。
迭代策略:一次一个聚焦改动,改后重跑失败的那条检查,换策略前先读测试输出;同一错误连败 2 次换证据来源。
完成条件:回归测试修复前红、修复后绿,lint/typecheck 全过,输出贴在对话里。
暂停条件:需要支付凭证、生产数据、schema 迁移,或叠加规则要产品拍板时。
```

## 反模式

- 验证写「make sure it works」「确保没问题」
- 边界写「edit whatever is needed」「随便改」
- 迭代写「keep trying」「一直试到好」
- 完成写「when it seems good」「看起来不错就行」
- 涉及登录、付费、破坏性操作、私有数据却没写暂停条件
- `/goal 把应用做好一点。`——目标是活动不是结果,七字段一个都没有
