# ten-step-learning — 十步学习法（端到端学习流水线）

用户只给一个学习主题 → 跑完十步闭环 → 产出一个自包含的单文件学习 HTML，
且随时可以切换成"陪你学"的交互模式。

**方法来源**：斯坦福 STORM（检索增强的多视角调研，NAACL 论文）+ Rahul（@sairahul1）的
四要素框架（一条路径、一次测试、一次压缩、一个反馈循环），由大刘融合成
「学习 → 深化 → 记忆 → 回顾」的十步闭环。灵魂是**闭环 + 逐环交接**：
十步不是十段独立内容，前一步的产物是后一步的输入，严禁跳序、严禁凭空生成而不消费上游。

## 三种模式（先判断用户要哪种）

| 模式 | 触发情形 | 产出 |
|---|---|---|
| **A · 全流程**（默认） | "系统学一下 X""给我做 X 的学习 HTML" | 十步全跑 → 单文件 HTML |
| **B · 单步** | "只帮我出 X 的速查表""只跑五视角" | 该步结果，直接在对话里给出（不必出 HTML） |
| **C · 交互教练** | "考考我 X""用费曼法陪我过一遍 X"；或模式 A 交付后用户接受邀请 | 对话式考试 / 费曼复述陪练 |

模式 A 交付 HTML 后，主动邀请一句：*"HTML 里的题库是给你日后自测的。
想现在就检验一下的话，我可以直接当考官一题一题考你（第 8 步交互版），
或者陪你做费曼复述（第 9 步交互版）。"*——检索练习和费曼循环的价值在"从脑子里往外掏"，
静态材料替代不了这一下，所以要主动递这个台阶。

## 阶段 0 · 学习画像（尽量不打断）

需要两个信息：**① 当前水平 + 目标深度**（零基础/有点基础/有经验；能聊两句/能上手干活/能和专业人士对谈），
**② 角色 / 使用场景**（用于第 3、5、6、7 步的个性化）。

- 用户开场已经给了（或从上下文能明确推断）→ **不要再问**，直接开跑。
- 缺一两项且处于交互会话 → 一次性问齐（一条消息问两个快问），答完即全程零打断。
- 非交互 / 自主运行场景 → 用默认值：目标"能和专业人士对谈"，角色按上下文合理推断，并在交付时注明所用假设。

把答案凝成一句「学习画像」（如：*运营背景、想达到能与专业人士对谈、用于给团队做分享*），
贯穿全程填入各步提示词的 `{{角色}}`/`{{水平}}`/`{{目标}}` 占位。

## 阶段 1 · 研究方式（混合，按需真实联网）

- **必须真实联网的两处**：**第 1 步**（五视角取证，证据要真、可溯源、带来源链接）、
  **第 5 步**（资源筛选，书/课/社区必须真实存在且尽量新，每个给出可访问的 URL 并核实）。
  用环境里可用的联网工具（WebSearch / WebFetch / browser-act 等，哪个可用用哪个）。
  **宁可少写一条，不可编造一条**——虚构的书名、课程和数据会让整份学习材料失去可信度，
  这是本 skill 最不可接受的失败模式。
- **靠模型推理的部分**：第 6–10 步是教学结构化（阶梯、核心 20%、题库、费曼、速查表），
  基于前几步产物 + 自身知识生成，不需要联网。
- **检索强度自适应**：主题越硬核/越前沿，检索越重；常识性主题轻检索即可。
- **语言**：正文跟随用户语言；专有名词（RAG、retrieval practice、STORM 等）保留原词，首次出现加解释。

## 阶段 2 · 顺序执行十步

逐字提示词见 [references/ten-step-prompts.md](references/ten-step-prompts.md)（含第 8/9 步的材料化版与交互版）。
按 1→10 顺序，每步做三件事：**跑该步提示词（已填主题与画像）→ 拿到完整原始产物 → 提炼学习结果**。
每步必须**显式消费上游产物**：

| 步 | 名称 | 消费的上游 | 输出（原始产物） |
|---|---|---|---|
| 1 | 五视角 STORM〔联网〕 | 主题 | 5 位专家各自的立场 / 最强证据（带来源）/ 独有洞察 |
| 2 | 矛盾图谱 | 步1 | 冲突对、最强/最弱证据、化解关键问题、共识、盲区 |
| 3 | 综合简报 | 步1+2 | 一段话总结 + 5 关键发现（带可靠性）+ 隐藏关联 + 行动建议 + 前沿问题 |
| 4 | 同行评审自检 | 步3 | 5 发现逐个 1–10 打分、最没把握项、过重视角、缺的第 6 视角 |
| 5 | 资源筛选〔联网〕 | 主题+画像 | 5 个真实资源（为何强/怎么用/花多久/关键点/URL）+ 被高估的坑 + 一周路径 |
| 6 | 学习阶梯 | 主题+步3 | 5 级难度 × 8 要素（名称/该懂什么/掌握长相/重点/里程碑/练习/常见错/自测题） |
| 7 | 2 小时核心 20% | 步3+6 | 核心 20% 概念 + 10 次课计划 + 每课 5 复习题 + 最终小项目 |
| 8 | 考到崩溃（材料化） | 步3+6+7 | 题库：10 题分级 + 参考答案 + 评分标准 + 5 道终极挑战 |
| 9 | 费曼循环（材料化） | 步3 核心概念 | 分层费曼讲解：12 岁版讲解 + 逐个拆困惑点 + 一句话精确定义 |
| 10 | 一页速查表 | 全部 | 一句定义 + 短条目要点 + 3–5 例子 + 易错点 + 上场清单 + 5 快问快答 |

**边跑边落盘（重要）**：每完成一步，立即把该步原始产物写进构建目录的 `steps/step-NN-<名称>.md`。
十步全程很长，落盘保证上下文被压缩后内容不丢，也让后续 HTML 分片有稳定的取材来源。
构建目录放临时位置（scratchpad 优先，否则 `./ten-step-build/`，交付后删除）。

**第 8、9 步在 HTML 里用材料化版本**（题库 + 分层讲解），并在输入面板注明
"原方法为交互式，交互版可在对话中体验"——这是静态交付的必要妥协，交互版留给模式 C。

## 阶段 3 · 分片组装 HTML

不要一次性生成整个 HTML（模板外壳 26KB + 内容会远超单次生成的可靠长度，极易截断或漏占位符）。
正确做法：

1. 读 [references/template-guide.md](references/template-guide.md)，了解占位符清单与组件类写法。
2. 在构建目录 `fragments/` 下，**为每个占位符写一个同名 HTML 片段文件**
   （如 `STEP_1_INPUT.html`、`STEP_MAP.html`）。片段只复用模板已有组件类，
   不新造样式、不改颜色圆角。VIZ 只有第 1/2/6 步和收尾需要，其余步不写该文件即可（脚本自动置空）。
3. 运行组装脚本（确定性替换 + 残留占位符校验）：
   ```bash
   python <skill目录>/scripts/assemble.py \
     --template <skill目录>/assets/template.html \
     --fragments <构建目录>/fragments \
     --topic "<主题>" \
     --out "<主题>-十步学习.html"
   ```
   脚本校验失败（缺片段/有残留 `{{`）就补齐片段重跑，不要手改产物 HTML。

## 阶段 4 · 交付

- `<主题>-十步学习.html` 写到当前工作目录（主题做文件名安全化），单文件即唯一正式交付。
- 一句话汇报：主题、跑了哪些步、联网核实了哪几处、文件路径，
  提示"侧边栏点任意一步可看该步的输入/输出/学习结果"。
- 问一句是否保留 `steps/` 下的 markdown 学习笔记（有人喜欢导入笔记软件），默认删除构建目录。
- 递出模式 C 的邀请（见「三种模式」）。

## 模式 C · 交互教练（第 8/9 步的本来面目）

交互版逐字提示词见 [references/ten-step-prompts.md](references/ten-step-prompts.md) 末尾两节。要点：

- **考官**：一次只问一题，等用户回答；每答打 0–10 分、指出对的/差距/漏掉的；
  答得弱先追问再进下一题，答得好加难度；10 题后给总分、强弱项、复习计划、5 道挑战题。
  绝不一次把所有题和答案倒出来——那就退化成阅读材料了。
- **费曼陪练**：先用 12 岁能懂的话讲一遍 → 让用户复述 → 只针对复述里含糊、跳步的点重教 →
  再让用户讲，循环到解释简单、准确、完整为止。用户讲不清之前不进新内容。
- 若之前跑过模式 A，考试范围以该次产物（简报/阶梯/核心 20%）为准；
  考完后可以主动提议把暴露出的薄弱点回填进 HTML 题库（更新对应 fragment 重新组装）。

## 完成判定（模式 A 交付前自检)

- [ ] 画像信息能推断就没多问；问也只问了一次。
- [ ] 十步全部执行且逐环消费了上游产物（不是十段孤立内容）；每步产物已落盘 `steps/`。
- [ ] 第 1、5 步的证据/资源经真实联网核实，带可溯源来源/URL，无编造。
- [ ] 第 8 步是题库+参考答案+评分标准+5 挑战；第 9 步是分层费曼讲解（材料，非对话实录）。
- [ ] 每步三栏语义正确且互不重复：输入=提示词+上游标签、输出=完整原始产物、学习结果=3–5 条提炼结论。
- [ ] 第 1/2/6 步与收尾有对应可视化；其余步 VIZ 留空。
- [ ] HTML 经 `assemble.py` 组装且校验通过（无残留 `{{`）；侧边栏 12 项可切换；CSS/JS 未被改动。
- [ ] 已交付路径、汇报联网核实点、递出交互模式邀请。
