# 方法论可靠性检验记录（留档）

> 2026-08-26。对合并结论（见 methodology.md）执行三路独立检验：
> 专家会诊、第一性原理、跨领域借解。本文件是检验过程与结果的完整留档。
> 结论先行：**方法论核心存活；三条路各打掉一块东西，也各添了一块。**

## 路线一：专家会诊

### 三个互补视角

| 视角 | 检验维度 | 为什么必要 |
|---|---|---|
| A. 运筹学者（排队论/随机调度） | 模型对不对 | 公式借了 CPM/ToC 的皮，需验数学成色 |
| B. 受託開発一线 PM | 跑不跑得动 | 方法论的死因从来不是错，是跑不动 |
| C. 激励设计经济学家 | 数字被怎么用 | 估算是承诺博弈，不只是测量 |

### 各视角核心挑刺

**A（运筹）**：这是资源受限随机调度问题（RCPSP），NP 难，无解析解。
- `max(依赖CP, 约束队列)` 数学上不严格——队列延迟叠加在关键路径上，不与之并列；公式只能当心智模型
- `min()` 求并行度漏了方差：Kingman 公式下瓶颈利用率逼近 100% 时等待爆炸，
  真正的规则是利用率 ≤80%；「3-5」不是算出来的，是「别排满 reviewer」的经验投影
- 蒙特卡洛的经典陷阱：任务间相关性（同模型/同 reviewer/同架构）使独立性假设下的区间系统性偏窄
- 改判条件：回测显示预测区间达到名义覆盖率

**B（PM）**：这是采用成本问题。
- 8 字段 × 每日更新 = RUP/CMMI 的死法重演；一线能维护的是 2-3 个字段，其余例外驱动
- 検証ベース计价在相見積もり场景不成立（采购买人月是为跨供应商可比），只对信任客户可用，导入顺序是硬约束
- 反转成机会：人肉维护 ETA 分布的工具不存在——**所以这套方法论只能作为 AI 运营的方法论存在**，
  这不是缺陷，是它必须做成 skill 的理由
- 改判条件：10 任务试点中记账成本 <5 分钟/天

**C（经济学家）**：估算数字是承诺装置。
- 给 P50/P80/P95，对方会锚定 P50 并当承诺——区间进合同即坍缩成点；
  必须硬性规定哪个数进合同（P80 + 前提条款），不能留白
- Verified Throughput 一样会被 Goodhart（验证仪式化、PR 切碎）；双指标 + 轮换审计
- 三本账假设对手方诚实；对抗性客户下保护靠合同模板，不靠分类学
- 改判条件：客户接受 re-baseline 且关系无损的实例

### 互相质疑后的收敛

- **共同事实**：验证是瓶颈；任务方差巨大必须先分类；记账成本必须趋近零否则全死
- **真分歧**：A 要更高模型保真度，B 要更低流程摩擦，C 说保真度无关紧要因为数字是政治对象
- **分歧背后的假设**：三人对「这套东西是干什么用的」假设不同——预测准 / 跑得动 / 承诺可辩护
- **综合**：不选边，方法论显式服务三个目标 → **一个模型三种视图**成为架构原则
- **最大风险**：仪式死（B）与 P50 锚定（C）
- **退出条件**：试点记账成本 >15 分钟/天，或区间覆盖率与名义值偏差 >20pp
- **第一步**：自己团队 10 任务、两周试点

## 路线二：第一性原理

### 无法绕开的基本事实

1. 工期是随机变量，方差来自未知信息；信息只能靠做事揭露
2. 人的注意力有界且不可储存（易腐资产）
3. AI 生成容量近似弹性便宜；其任务类可靠性先验未知但可实测
4. 人工验证成本 ∝ 产物大小 × 不熟悉度 × 风险；一部分被制度锁死不可自动化
5. 对外承诺不对称：说早了要罚，说晚了没奖
6. 模型能力变化速度 > 任何已发表测量的时效

### 未验证就继承下来的假设（检验打到痛处的部分）

1. **「任务」是正确原子** → 否。刚性的只有人类拍板和不可逆节点，
   agent 使决策之间的执行成为弹性填充 → **排程对象应是决策日历，不是任务清单**
2. **估算必须发生在执行前** → 否。agent 使探测极便宜，
   默认动作应从「猜」变成「探」（estimation-by-probing），只对探不起的才真正估算
3. **每个任务内部都需要 ETA 数字** → 大半是遗留仪式。内部真正需要的只有：
   今天稀缺注意力给谁（排序）+ 对外承诺的少数几个日期
4. **概率分布需要蒙特卡洛** → 否。按 regime 分类取经验分位数（reference class forecasting）
   更简单、自动含相关性、自动跟随模型换代

### 重新推导的最小系统

```
可探测的任务 → agent 试跑 → 实测替代估算
不可探测的任务 → regime 分类 → 经验分位数
排程骨架 = 决策日历 + 瓶颈队列纪律
对外承诺 = 经验 P80 + 前提条款 + 预先约定的 re-baseline 触发器
唯一人工估的量 = 残余人类注意力（S/M/L）
```

- **原方案中属表面修补**：8 字段模板（大半可推导或仅例外时需要）、max() 公式（装饰性数学）
- **成立前提**：探测便宜且安全（沙箱）、实测数据有 AI 记、客户接受前提条款制
- **验证第一步**：最近 10 个已完成任务回测——「30 分钟探测 + 经验分位数」是否优于当时的人工估算

## 路线三：跨领域借解

### 剥掉术语后的底层结构

生产端弹性便宜 × 认证端稀缺昂贵 × 加工中随机长出新工作 × 外部要求日期承诺 × 质量检验前不可知。
核心矛盾：生产速率 ≫ 认证速率，压力变成延迟或未认证放行。
加人/加班/催失效的原因：瓶颈在认知资源，不可线性扩容。

### 三个远域案例

**1. 半导体晶圆厂（解了 30 年）**
- 机制：CONWIP（新批次只在旧批次离场时进入）、吞吐-WIP 运营曲线、加急批 <5%
- 迁移：验证受限的拉式系统——验证队列满员不启动新 agent 任务；hot-lot 教训 = 「这个急先合」限额
- 失效条件：工作项异质性大——所以必须先 regime 分类再套

**2. 医院手术室调度**
- 机制：按病例类别分块预留容量、case-mix 分类、~20% 容量永不排计划（给急诊）、利用率红线 ~80%
- 迁移：reviewer 日历分块 + 20% 应急块吸收 Blocking 发现 + 80% 红线——给 Kingman 挑刺一个现成运营答案
- 失效条件：分类不可靠时块状预留变浪费

**3. 新药研发管线**
- 机制：阶段门 + 预先写死的 kill 条件、每阶段维护技术成功概率（PTS）随证据更新、便宜的早期筛选做多
- 迁移：探索预算配预先约定的继续/杀死/转向条件；ETA 旁并列报 PTS，
  把「工期不确定」和「方向不确定」拆成两个数
- 失效条件：任务太小时门禁开销反噬（对上适用下界）

**附：保险精算（商务层专用）**——検証ベース计价的本质是给风险定价而非给工作量定价；
滚动校准 = 经验费率法；风险缓冲单独标价 = 再保险。
话术：「我们不卖工时，卖的是承保了验证责任的交付。」

### 低成本可逆实验

自己团队两周：验证队列满员即停发新任务（CONWIP）+ reviewer 日历留 20% 空白 + 记实测周期。
看 P80 周期是否收窄、零审查合并是否归零。完全可逆。

## 三路汇总：检验改变了什么

**三路独立收敛（可靠性最高）**：人类瓶颈靠队列纪律管（拉式/WIP/≤80%），不靠估得更准
——运筹给 Kingman、晶圆厂给 CONWIP、医院给容量块。
「验证 WIP 上限」由此从治理项之一升格为**中央运营机制**。

**被打掉/降级**：
1. max()/min() 公式 → 降级为心智模型，计算靠经验分位数
2. 蒙特卡洛 → 非必需，reference class + 滚动实测更稳且免疫相关性陷阱
3. 8 字段模板 → 核心 2-3 字段（regime、残余注意力、对外承诺与否），其余例外驱动

**新增**：
1. 决策日历（排决策，不排工作）
2. 探测优先（能试跑的不估算）
3. 一个模型三种视图（P80+前提条款进合同）
4. CONWIP 拉式 + 80% 红线 + 20% 应急块
5. PTS 与 ETA 并列（方向不确定性与工期不确定性分开报）
6. 元结论：方法论人肉跑不动，只能以 AI 记账运营的形态存在——这正是它必须是 skill 的原因
