# WBS＋日別ガント Excel 渲染手册

被要求出 WBS 时的**执行器**。规则层（为什么这么渲染）见 external-layer.md §9；
本文件管怎么生成。生成器：[scripts/generate_wbs.py](../scripts/generate_wbs.py)。

## 作成フロー（被要求出 WBS → 交付 → 运用）

**前提**：排程状态文件已存在（本 skill Phase 4 的产物）。WBS 永远是它的**渲染视图**，
真相源不在 xlsx 里。

1. **规则先行**：读 external-layer.md §9——定义回归（WBS=what 非 how/when）、渲染 7 条、
   守线、对传统派的话术（PMI 弹药）都在那
2. **番号分配**：叶子按成果物切；有子行即组（自动格子纹）；判断点（人的批准・不可逆点）
   独立成行；**番号一经分配永不改动**，追加/派生走 `-a/-b`（规约见下节）
3. **起草 spec.json**（schema 见下）：从状态文件任务表转写——bars 按周粒度落 from/to、
   style=plan/verify、milestones 单日、kind/issue/dep/effort/目安文言；
   按需开 `task_dir`（任务详细 md 联动）和 `daily_sheets`（日别页）
4. **生成**：`python scripts/generate_wbs.py spec.json`
   → WBS（表+日别甘特+当日红线+「本日」列）＋可选 日别页/本日页 ＋ 前提・凡例
5. **task_dir 时补齐 tasks/**：每叶子一个 `<番号>.md`，**开头两节固定
   「全体にとっての意味」「核心」**（只有手顺的 md 不合格），另放 README 番号规约
6. **校閲**：日文按平叙业务文体过一遍——同形异义词、比喻/夸张清除
   （有 write-natural-business-japanese 技能就调它）
7. **验证（必做，代替跑不了的 recalc）**：
   - python 侧模拟 2〜3 个日期（含一个里程碑日）：枚举「開始≤当日≤終了」的叶子 vs 预期清单
   - 红线列对账：实心条数 ＝「本日」列●数（＝日别页当日件数）
   - 抽查超链接与 `=WBS!` 引用解析到正确行（注意：行范围别硬编码，扫到空行为止）
8. **运用循环**：状態只在主表改（日别页/清单自动联动）；开发中发现/变更 → `-a` 派生
   ＋下游依存张り替え；**档期结构变了 → 改 spec 重新生成，不手修 xlsx**

## spec.json schema

```json
{
  "title": "三機能開発",
  "start": "2026-08-27",
  "days": 43,
  "out": "WBS_xxx.xlsx",
  "today_slots": 20,
  "notes": [["体制", "担当 1 名＋AI…"], ["日付", "目安（週粒度）…"]],
  "tasks": [
    {
      "wbs": "1.1",
      "name": "通信制限設定の本番反映",
      "kind": "是正",
      "issue": "#343 #342",
      "dep": "",
      "effort": "0.5",
      "start_note": "8/27",
      "end_note": "8/27",
      "status": "未着手",
      "bars": [{"from": "2026-08-27", "to": "2026-08-27", "style": "plan"}],
      "milestones": []
    }
  ]
}
```

- `bars[].style`：`plan`（濃青＝設計・実装・調査）／`verify`（薄青＝検証・調整）
- `milestones`：日期数组，各画一个 ◆（当日才进「本日」判定）
- `daily_sheets`（可选，true）：每个计划日生成一张日别 sheet（tab 名 `0827` 式），
  行内容全部 `=WBS!…` 引用主表——改主表即联动；成员/排序按计划静态落位，改计划→重新生成。
  注意 tab 数=日数；与 today_sheet（本日のタスク）可并存也可二选一
- `task_dir`（可选）：相对目录名（如 `"tasks"`）。指定后叶子行的 WBS 番号变成超链接
  → `<task_dir>/<番号>.md`——每条任务一个详细 md（やること/完了条件/範囲外/検証/変更履歴）
- **父行/分组行自动识别**（存在 `X.` 开头的子行即视为分组）→ 条形自动转格子纹、
  不参与「本日」计数；不需要也不允许手动标记
- 日期只到週粒度目安时，bars 直接给周的起止日——**显示是日单位，计划粒度仍是周**，
  凡例注记已内置这句话

## 内置机制（生成器封装的坑，改动前先读）

| 机制 | 实现 | 曾踩的坑 |
|---|---|---|
| 当日红线 | CF 挂 `TODAY()`：表头红底白字 + 数据区粗红左边框 | **CF 的 dxf 填充必须用 `bgColor`**——用 fgColor 会得到白字白底的「隐身列」 |
| 计数一致性 | 叶子实心条／父层格子纹（lightTrellis）；甘特条数＝●数＝清单件数 | 父子条同色时肉眼计数必然对不上 |
| 「本日」列 ● | 叶子行公式 `IF(AND(開始<=TODAY(),終了>=TODAY()),"●","")` | 分组行必须留空，否则重复计数 |
| 动态清单 | 隐藏列（開始/終了/連番）+ INDEX/MATCH；連番＝終了日昇順 rank（SUMPRODUCT，同日按行序破并列） | rank 不唯一则 MATCH 错位 |
| 函数纪律 | 只用 IF/AND/COUNTIF/SUMPRODUCT/INDEX/MATCH/IFERROR/TODAY/ROW | FILTER/XLOOKUP/SORT 在 LibreOffice 算不出且 openpyxl 无 spill 元数据 |
| 日别表名 | 跨年时才加年份（`%y%m%d`），否则 `%m%d` | 跨年用 `%m%d` 会撞名，openpyxl 会静默改成 `12301` 这种像日期又不是日期的名字 |
| 表头 | 月合并/日/曜日三行、土日灰、freeze 在日列前、Yu Gothic | — |

## Recalc 注意

产物含 `TODAY()` 类公式 → 按 xlsx 技能规范应跑 recalc.py 烘焙缓存值。
但 Windows 无 LibreOffice 时跑不了（`AF_UNIX` 不存在）——此时如实声明：
Excel 打开时实时计算（TODAY() 公式本来就必须每次打开重算），
副作用仅是脚本直读缓存值会得到空。**验证改用 python 侧模拟**：
按 TODAY=某日枚举「開始<=当日<=終了」的叶子行，与预期清单比对（生成后必做）。

## 任务详细 md 与番号规约（task_dir 模式）

- 每个叶子任务一个 md，文件名＝番号（`2.1.1.md`）；xlsx 番号格直接超链接过去
- md 的**开头两节固定为「全体にとっての意味」（不做它哪个门/卖点会塌）和「核心」（一句话本质+真难所）**，
  然后才是 やること/完了条件/範囲外/検証。只有手顺的 md 不合格——手顺会变，意味和核心不变；
  这两节也是 agent 接手任务时唯一不可省读的部分
- 意味/核心 用**平叙业务文体**：禁比喻与夸张（地雷/爆発/嘘をつく…）——给读者留下印象的应是事实本身，不是修辞
- **番号一经分配永不改动**（欠番允许）——中途插入用「親番号+英字」派生：`2.1.1-a`、`-b`…
  新独立任务用组内末尾未使用号。理由：renumber 会腐蚀 xlsx/md/Issue/对话里的一切引用
- 派生 md 冒头必须写**由来**（技術的発見／要求変更／学び——与三本账同分类）
- md 只追加不删除；完成时勾掉完了条件并更新 xlsx 状態列
- 模板与完整规约：项目侧 tasks/README.md（生成物之一的范例）

## 制約：1 タスク行のバー／◆ は連続していること

隠し列（開始／終了）は**連続した 1 区間**しか表現できない。バーが分断していたり
◆ がバー期間の外にあると、その間の空白日まで「本日」対象に数えられ、
凡例（「バー期間が本日を含む葉タスク」）と食い違う workbook が黙って出来上がる。

生成器はこれを検出して `ValueError` を投げ、空白日を名指しする。直し方は行を分けること：

```
NG: 1  作業  bars=[9/1-9/2, 9/6-9/7]        → 9/3〜9/5 も「本日」対象になる
OK: 1.1 前半  bars=[9/1-9/2]
    1.2 後半  bars=[9/6-9/7]

NG: 2  実装  bars=[9/1-9/2]  milestones=[9/8]  → 9/3〜9/7 も対象になる
OK: 2.1 実装  bars=[9/1-9/2]
    2.2 判定  milestones=[9/8]
```

WBS としても、間が空く作業は別の成果物であることが多いので、行を分ける方が素直。
