# AI/Agent Coding 时代排程方法论（定稿 v1.0）

> 本文档是方法论的回述记录与定稿，形成于 2026-08-26。
> 演化路径：一线观察（10 个各估 5 人日的任务，多 agent 并行 10 人日全部关闭）
> → 对话推演出 18 条初始结论 → 两路独立全网调查交叉复核
> （8 角度并行检索 + 另一 AI 独立检索，重合部分构成独立复核）
> → 两轮时效性质疑（METR 数字 vintage 问题，催生「快慢分层」原则）
> → 三路可靠性检验（专家会诊 / 第一性原理 / 跨领域借解，全文见 validation-record.md）。

## 一、总纲（四句）

1. **AI 时代不是项目无法估工，而是估算对象变了**：过去估「人写代码的工时」，
   现在要预测「一个受验证带宽、共享资源队列、未知分支和人类决策约束的动态交付系统何时收敛」。
2. **管理目标换轴**：从最大化 Coding Utilization 转向最大化 **Verified Throughput**
   ——单位时间内已验证、可理解、可维护、真正交付的价值——同时控制 WIP、未知分支、认知债务和交付风险。
3. **AI 是放大器不是均匀加速器**：同一套工具在不同任务与团队上产出 -19% 到 20x 的散布，
   因此诊断永远先于估算。
4. **方法论锚定慢变量，快变量全部现采**：这保证整套方法不随模型换代过期。

## 二、快慢变量分层（最高设计原则）

| 层 | 变量 | 半衰期 | 处理方式 |
|---|---|---|---|
| 慢 | 人的 review 注意力上限、决策延迟、上下文切换成本 | 年~不变 | 可写死进方法 |
| 慢 | 合同结构、合规/追责性人工 gate、承诺不对称性 | 年 | 可写死进方法 |
| 慢 | 「生成端随模型伸缩、人这一侧不伸缩 → 每代模型裂口更大」的方向性判断 | 被模型进步加强 | 可写死进方法 |
| 快 | 加速倍数、一次过率、闭环轮数 | 一个模型代际（~6 个月） | 现采 + 短窗校准 |
| 快 | accident/essence 的边界（模型自挖上下文能力在涨） | 缓慢漂移 | 定期重判 |
| 快 | 可自动验证比例（验证工作也在被 AI 接管一部分） | 一个代际 | 现采 |

**推论（测量管线定律）**：实证研究从设计到发表需 6-12 个月，模型代际约 6 个月，
所以**任何已发表的加速数字在读到时已经过期**——文献只能提供方向证据和机理，不能提供系数。
METR 2026-02 进一步承认对照实验本身已做不出（开发者拒绝进无 AI 组），
意味着以后连「过期但干净」的数字都不会再有，校准只能靠团队自己的持续在线数据。

## 三、核心模型（心智模型，非计算式）

以下公式帮助思考，**真实计算靠经验分位数与队列观察**——严格地说队列延迟叠加在
关键路径上而非与之并列，精确解属于 NP 难的资源受限调度问题，不存在解析式。

```
T_delivery ≈ max(依赖关键路径, 约束队列路径)
           + 发现返工 + 决策延迟 + 集成延迟 + 残余风险

有效并行度 = min(就绪独立任务数, Agent Fit, 验证带宽,
                Review 带宽, 环境容量, 决策带宽)     ← 经验起点 3-5
                真正的运营规则：瓶颈利用率 ≤80%（Kingman：利用率→100% 时等待爆炸）

交付成本 = 生成 + 验证 + 理解(认知债) + 集成 + 长期所有权   （Trust Cost 五项）
```

约束队列包括：Review 队列、测试环境、CI、安全审批、产品拍板、客户响应。
即使任务在 DAG 上零依赖，也会全部堵在同一个 reviewer 或同一个拍板人身上——
这是传统关键路径法看不见的第二条路径。

## 四、Regime 分类（诊断先于估算）

任务的 AI 加速表现不是连续谱，是**双 regime 分布**：33,707 个 agent PR 的实证显示
28.3% 即时合并，其余频繁陷入反复反馈循环甚至沦为被放弃的「幽灵 PR」，中间地带很薄。
理论侧，Novelty Bottleneck 模型给出相变结构：人类投入随任务新颖度跨过阈值时
从 O(E) 骤变为 O(1)，无平滑过渡；更强的模型改变系数、不改变指数；
并行可把墙钟时间压到 O(√E)，但总人力投入保持 O(E)——可以用并行换工期，换不掉人力成本。

**分界变量按预测力排序**：
1. **代码库新旧**：2x 吞吐提升几乎全部来自新代码库，遗留库收益很小，
   且该差异与开发者资历无关（"The codebase itself was the bigger dividing line"）
2. **accident/essence 占比**：AI 提速幅度 ≈ 任务中样板性工作（accident）的占比；
   领域判断、隐性业务规则、组织内未成文的上下文（essence）不在任何训练数据里
3. **静态复杂度信号**：patch 大小、触及文件数、文件类型——仅用创建时刻的静态信号
   即可以 AUC 0.957 预测审查工作量，远好于语义特征

**证据调和**：MSR 三企业 RCT（4,867 人）测得 +26%，METR RCT（资深开发者+熟悉的成熟库）
测得 -19%——两者不矛盾，是不同人群落在不同 regime。这正是「诊断先于估算」的最强论证。

## 五、估算单位：残余人类注意力

唯一需要人工估的量：**从头到尾读完/审完/测完/协调完这个改动所需的专注人类时间**
（S ≤1h / M 半天 / L 1-2 天，禁 XL——出现 XL 说明该拆）。
这是 Sahaj「Residual Attention Estimation」的核心：估计 AI 消除不掉的那部分。
Agent Work 是弹性便宜资源，不值得精估；人类注意力是易腐的稀缺资产（今天没用掉的
review 容量明天补不回来），它才是排程的分母。

**探测优先**：能让 agent 试跑 30-60 分钟的任务不要猜——估算的默认动作从「猜」变成「探」，
预测成为做事的副产品。探测报告六因子：审查负荷、认知负荷、爆炸半径、测试负担、
协调成本、风险不可逆性。Planning 由此变成 Audit：人只需验证或反驳 agent 给出的判断。

## 六、队列纪律（中央运营机制）

三路独立检验（排队论 Kingman / 晶圆厂 CONWIP / 医院容量块）收敛于同一结论：
**人类瓶颈要靠队列纪律管，不是靠估得更准**。

- **CONWIP 拉式**：验证队列没空位就不启动新的 agent 任务（比静态 WIP 上限强：自调节）
- **利用率红线**：reviewer 排程 ≤80%
- **应急块**：~20% 注意力永远不排计划，专门吸收 Blocking 级发现（医院给急诊留床位）
- **加急限额**：「这个急先合」类插队 ≤5%（晶圆厂 hot lot 教训：插队摧毁全线吞吐）

**为什么必须硬性执行**：验证队列被顶到极限时，团队的真实反应不是把工期拉长，
而是降低门槛硬撑——实测队列压力下零审查合并 +31%、每 PR 事故率 +242.7%。
队列约束是软的，会被人击穿，代价从「排期变长」转移成「生产事故」。WIP 上限就是防这个。

## 七、决策日历

真正刚性的排程对象不是任务，是**人类决策点和不可逆节点**——agent 使决策之间的执行
成为弹性填充物。先排「哪天拍什么板」，工作在决策点之间浮动；把拍板批处理，
减少打断次数（实测：专家的杠杆不是缩短单次拍板，而是把多次小决策压缩成更少但更重的决策点，
让 agent 的自主执行链更长——专家每条指令触发 ~12 个动作 vs 新手 ~5 个）。

## 八、三本账与 Goal 版本化

| 账本 | 触发 | 动作 | 性质 |
|---|---|---|---|
| 技术发现 | 开发中揭露的既存事实（"原来必须支持事务"） | 重估，更新 ETA | Uncertainty 揭露 |
| 需求变更 | 客户/上级新增要求 | Scope 版本升级，显式记录 | Scope Change |
| 产品学习 | 交付后的反馈证明 Goal 本身要改 | Goal 版本升级 | WHY 环反馈 |

任何一本都不许被记成「研发延期」。Goal 在当前承诺窗口内稳定、Solution 浮动；
外部反馈改变 Goal 时显式升版本，不偷偷扩 Scope。
发现分诊三级：Blocking → 当前任务吸收进关键路径；Important → 新 issue；Optional → backlog。
没有这个分诊，vibe coding 的典型失控是「修 A→发现 B→顺手修 B→发现 C→两天后忘了 A」。

## 九、一个模型三种视图

估算数字同时服务三个互相冲突的目标：预测准（运筹视角）、跑得动（运营视角）、
承诺可辩护（博弈视角）。解法不是选边，是**一个模型三种视图，永不混用**：

1. **内部预测**：全概率（P50/P80/P95）+ 假设清单 + 高不确定项及重估触发条件
2. **运营看板**：今天注意力给谁、队列水位、WIP 状态、发现分诊
3. **対外承诺**：只出 P80 + 前提·除外·受け入れ基準 + 预先约定的 re-baseline 触发条件。
   区间一进合同就会坍缩成点、且锚定在 P50 上——所以进合同的数必须预先设计。

## 十、度量：Verified Throughput + 双指标

北极星是 Verified Throughput（单位时间已验证交付的价值），它把「AI 写了多少代码」
从 KPI 里踢出去。但任何单指标都会被 Goodhart（验证仪式化、PR 切碎），
所以**过程指标（AI 介入深度占比）与结果指标（已验证交付周期）必须成对使用**，
一涨一平即是被 hack 的信号（实测案例：AI 生成率 30%+、体感提效 20-40%，交付周期基本不变）。

## 十一、対外层

见 external-layer.md。要点：三数并列（传统等价工作量/实际人投入/日历 ETA）、
検証ベース计价（给证据标价而非给代码标价）、三段見積書（前提/除外/受け入れ基準）、
スコープ蠕動条款、GPS-ETA 沟通术。
诚实标注战略前提：人月合同不换，估算做得再准也是给一个在消亡的商业模式续命——
提效在人月计价下会计上直接等于减收（实例：工数削减 70% → 销售额砍到约三成）。

## 十二、适用下界

小而清晰的单任务直接做。实测对照：同一功能 Spec 全流程 33.5 分钟 agent 执行 +
3.5 小时人工审查 + 2,577 行文档，传统迭代式 24 分钟总耗时、零文档，质量无差——
重流程对小任务慢约 10 倍。本方法的启动条件：≥3 任务排序 / 对外承诺 / 多 agent 并行 / 探索型。

## 十四、已知局限与开放问题

1. **P50/P80/P95 持续修订 ETA 未成行业标准**——属本方法的前沿部分（Sahaj 蒙特卡洛
   置信日期是萌芽），对外使用时标注为「本方法特色」而非「业界标准」。
2. **任务相关性使区间偏窄**：同一模型/同一 reviewer/同一架构使任务不独立，
   经验分位数部分缓解但未消除；预测区间的实际覆盖率需回测验证。
3. **三本账假设对手方基本诚实**：对抗性客户会把技术发现重新起诉为「你们当初就该知道」，
   保护靠合同模板（三段見積書），分类学本身保护不了。
4. **认知债的长期成本未完全建模**：代码增长速度 > 人类理解速度的复利效应
   （重构占比 21%→3.8%、复制粘贴 9.4%→15.7%）只进入 Trust Cost 定性项，无量化方法。
5. **概念完整性 review 不可并行扩容**（Brooks）：这类判断加 reviewer 反而更难维持一致，
   「验证带宽」对它不适用，需单独处理。
6. **元结论**：本方法论的记账成本人肉跑不动，只能以 AI 记账运营的形态存在——
   这既是它的落地形态（skill），也是它对「仪式死」免疫的唯一途径。
