# 中文 → 自然な商務日本語

## 合格线只有一条

**日本人从头读到尾，一次都没有冒出「え？」。**

包括这几种「え？」：「これ何のこと？」「誰がやるの？」「どれのこと？」「で、結局何が言いたいの？」「具体的に何をするの？」。

词汇查过表、语法没错、读着自然——都不是合格线，是达到这条线的手段。判定方向只有一个：**读者卡住的地方就是缺陷**，哪怕每个词都能在词典里找到、每张表都过了。反过来不成立——「我检查过了」不能证明读者不卡。

这条线适用于**会到日本人手上**的东西。只给自己或中方看的理解用译文可以降档——见下节。

下面所有内容都服务这一条。三层分工是手段，三张表是手段之一。

## 两档：速訳 / 清書

先定档，再动手。档位决定做哪些步骤，不决定质量下限——两档都有必须守的底线。

| | **速訳**（轻量） | **清書**（重量） |
|---|---|---|
| 用在哪 | 只为看懂内容的译文；内部 chat・口头传达；大批文档粗筛；先出草稿等你判断要不要精修 | 会到日本人手上的东西：客户・日方同行的文档、メール、提案書・報告書・仕様書，以及会被反复引用的命名和标题 |
| 做什么 | 定骨架 → 逐段翻案 → 表 A/B/C 扫描 → 标点・文体统一 | 速訳全部 ＋ 表外词三级处置（含检索）＋ 命名特则 ＋「？」打点通读 ＋ 留痕清单 |
| 不做什么 | WebSearch 检索、命名验证、「？」打点、留痕清单 | 该做的都做 |
| 遍数 | 一遍过，不回头 | 至少两遍，第二遍以读者身份读 |

**怎么定档**

1. 用户明说「快速／速訳／先看个大意／不用太讲究」→ 速訳。
2. 文本要发给日本人，而对方不方便随口追问 → 清書。
3. 拿不准就问一句：「これは社内用ですか、お客様に出しますか」。不方便问就按清書做——但只补「？」打点里最便宜的两项：前提说明和施动者明示。

**速訳也不能省的底线**

省的是耗时的验证，不是省已知答案的替换。查表几乎不花时间，省它没有收益：

- 表 A-1 高危同形异义词（质量・登录・结束・项目・经理…）必须换。这类错一眼露馅，且改起来最便宜。
- 表 B 里的中文行话必须换。直搬是日本人完全读不懂，不是「读着别扭」。
- 中文标点不残留；文体不混用（です・ます／である）。

**速訳必须附一句声明**

交付时写明：「速訳（用語チェックのみ、読者視点の通読は未実施）」。让用户知道这份东西没过第二层——否则速訳产物会悄悄被外发，两档就白分了。

**速訳中途要升档的三种情况**

碰到就停下来说明，不硬翻：

- 要给产品・工具・页面・标题起日语名 → 这属于命名特则，必须走清書。
- 原文有内部编号・缩写・只有我方知道的前提，而这份东西看起来是要外发的。
- 我自己都读不懂原文在说什么 → 不猜着翻，直接问。

## 三层分工

各管各的：

| 层 | 原则 | 自由度 |
|---|---|---|
| **文章构型** | 与中文版镜像：章节顺序、表格框架、条目数、编号、数字一一对应 | 零（保证双语版本能逐节对照、同步维护） |
| **句子** | 先确定这句中文要传达的意思，再丢开原文句法，用日语把这个意思说出来 | 高：可拆句、换语序、换主语、加日语缓冲表达；不得增删信息点 |
| **词汇** | 照搬进日语的每个汉语词都要判定一次。表内查表，表外按产生规则判 | 判定标准唯一：日本人原生写同类文档会用这个词吗 |

为什么分层：结构动了，双语版本无法对照、后续同步必漏；句子不放开，必然残留中文句法；词汇不逐个判定，句法再自然也会踩「質量」「登記」这类一眼露馅的雷。

镜像只约束到**章节・表格・条目**这一级。段落内部的句子顺序该重排就重排——为了把结论提到段首、为了补出施动者而拆句，都是必须做的，只要信息点不增不减。「镜像」不是不许调整语序的理由。

## 工作流程

标〔清書〕的步骤速訳可跳过，其余两档都做。

1. **定骨架**：照搬中文版的标题层级、表格框架、条目顺序。标题译成自然日语，但数量和位置不动。
2. **逐段翻案**：一段一段处理。先在心里说出这段的意思，然后用日语直接写这个意思。写完回读：若能和中文逐词对上，说明是词语替换而不是重写，重来。
3. **词汇审查**：成稿后逐个看照搬进日语的汉字词。表 A/B/C 里有的按表改。〔清書〕表里没有的按「表外词怎么判」的产生规则和三级处置过一遍——**表外不等于安全**。
4. 〔清書〕**读者通读（「？」打点）**：换成「第一次看这份文档的日本人」的身份从头读一遍，在每个可能冒出「え？」的地方打点。见「读者会在哪里卡住」。这一步是合格线本身，不是最后的润色。
5. **收尾**：文体检查 + 自检清单。速訳在这里加上「速訳」声明。

第 3 步和第 4 步管的是不同的病，不能互相替代：第 3 步保证没有露馅的词，第 4 步保证读者不卡。词全对而读者卡住是常态——**这正是速訳交付时必须声明的原因**：它只做完了第 3 步。

## 读者会在哪里卡住

词汇层管不到的卡点。这些地方每个词都对、语法也对，读者照样卡——而且卡得比用错词更狠，因为他不知道自己漏了什么。

| 卡点 | 读者的内心台词 | 成因 | 处理 |
|---|---|---|---|
| 前提缺失 | これ何の話？ | 中文原文依赖中方共同背景，省掉了前提：内部编号、项目代号、只有我方知道的经过 | 首次出现处补一句人话说明；缩写先写全称＋（以下「〜」） |
| 施动者不明 | 誰がやるの？ | 中文可以整段省主语；日语商务文必须能判断责任方 | 明写 弊社／お客様／〜担当；用被动时也要让责任方可推定 |
| 指代断裂 | どれのこと？ | 「この」「該当の」「上記の」隔了几段还在指 | 换回具体名词。指示词不跨段 |
| 结论后置 | で、結局何が言いたいの？ | 中文按时间顺序铺陈，结论在最后 | 段首先给结论・结果・要请事项，经过放后面 |
| 抽象堆叠 | 具体的に何をするの？ | 「効率化の推進」「体制の強化」只有方向没有动作 | 落到「谁・对什么・做什么・到什么时候」 |
| 数字无根据 | 何に対して？いつ？ | 30%、来週、大幅 缺分母、基准、比较对象 | 补分母和基准；日期写绝对值（8月2日(金)） |

比率是这七项里最容易漏的一个——实测三次，「来週」每次都被标出来要确认，「30% 削減」的分母**三次全漏**（照抄成「3割程度削減」就过了）。看到 %、〜倍、増／減 就停一下，明确写出「对什么的、和什么比」；原文没有就标（要確認）。「3割程度」读起来像有根据，其实什么都没说。
| 论理跳跃 | なぜそうなる？ | 中文靠语序暗示因果，不写连接词也读得通 | 补 したがって／そのため／一方で |

判断卡点不靠「我觉得应该看得懂」。标准是：**这句话所需的信息，全部都在读者手上吗**？信息在我脑子里、在中文原文的上下文里、在群聊记录里——都算不在读者手上。

补前提时有一条硬约束：**缺的信息不许编**。责任方是谁、分母是什么、基准日是哪天——原文没有就是没有，猜一个填进去比留空危险得多。处理方式是问用户，或原地留「（要確認）」并在交付时列出来。为了消掉一个「？」而造出一句假话，是把读者的疑问换成了误解。

编造最常见的形态不是整句捏造，而是**顺手加一个限定语**。实测里出现过这一例：中文「在原来的流程里加了一道」，写成了「既存のフローに**確認**ステップを1つ追加」——原文没说加的是什么样的一道，「確認」是从上下文推出来的。推得再合理也是新信息。补前提的措辞要贴着原文的粒度：原文含糊，译文就含糊到同一程度（「ステップを1つ追加」），把该问的留给（要確認）。

这一条靠自觉守不住——写的人当场察觉不到自己加了词。所以 Verification 里有一步反向对照专门抓它。

**但别收得过头。**「不许编」和「补前提」不矛盾，界线是**信息来源**，不是「加没加字」：

| | 例（同一份原文） | 判定 |
|---|---|---|
| 补前提（该做） | 「AI-30」→「管理番号 AI-30（KYC 要件に伴うプロセス追加）」 | 括号里的内容来自原文另一句，只是搬到了首次出现处 → 合法 |
| 编造（不许） | 「加了一道」→「**確認**ステップを1つ追加」 | 「確認」原文没有，是从上下文推的 → 违规 |

实测里出现过两头都掉：一轮补了 AI-30 但编了「確認」，一轮不编「確認」了却把 AI-30 说明也删了。正确答案是两件都做。所以补注时问的是「这句话的内容在原文里有出处吗」——有出处就搬过来，没出处就留（要確認）。**不是**「少写点更安全」。

## 语义范围不许动

改写、润色、精简、按用户要求换文体——这些时候最容易坏的不是词，是**范围**。词错了一眼看得出来，范围被改宽改窄没人看得见。在合同、保修、免责、规格、安全注意事项里，改动范围就是改动权利义务。

**文体、语气、长度都可以按用户的要求改；范围不行。** 用户说「改成敬体」「太啰嗦精简一下」，改的是外壳，不是内容能覆盖到哪。

动手前把下面这些标出来，改完逐个回对原文。**任何一项对不上，日语再顺也是不合格。**

| 类型 | 原文长什么样 | 常见的坏法 |
|---|---|---|
| 部分否定 | すべて〜とは限らない／すべての〜を保証するものではない | 变成全否定（〜しません）或肯定 |
| 二重否定 | 〜ないわけではない／〜が制限されるものではない | 反转，或以「啰嗦」为由整句删掉 |
| 条件的成立范围 | 〜した場合に限り／〜ない限り | 限定被删，或弱化成无条件 |
| AND / OR | かつ・及び ↔ または・又は | AND 变 OR；两个要件减成一个 |
| 原则与但书 | 原則として〜。ただし〜はこの限りでない | 但书被删或被反转。成对出现，只能成对保留 |
| 逆接 | 〜であっても／〜にもかかわらず | 逆接消失，变成单纯的肯定 |
| 责任主体 | 甲／乙、お客様／当社、弊社 | 主客对调；含糊化成「双方で」 |
| 指代的所指 | この場合、当該〜、上記の | 换成具体名词时**擅自选定了一个范围** |
| 数量的边界 | 3回を超える／以上／未満／〜まで | 超える↔以上互换，端点含不含被改 |
| 数值・単位・法定表記 | 12か月、5,500円（税込）、電気用品安全法 | 换算、四舍五入、省略 |
| 固有名詞・UI 文言 | 製品名、「設定」＞「システム」 | 意译，或改成「更自然」的说法 |

**「指代的所指」是最阴的一个。** 把「この場合」换成具体名词通常是对的（见指代断裂那一条）——但如果原文的指代本身就含糊，你选定的那个具体范围就是新信息，而且读起来毫无破绽。

实测里出现过这一例：合同条文「ただし、この場合においても、乙が…責任を負うことを妨げない」被改写成「乙が**甲の承諾を得て**再委託した場合であっても、乙は…責任を負う」——原文的「この場合」没说是哪种情形，改写后责任范围缩到了「已获承诺」的再委托，未经承诺的那一半悄悄免责了。日语更通顺，法律含义变了。

含糊的指代只有两条路：**原样保留，或标（要確認）问用户**。不能自己挑一个填进去。

## 审校别人的日语时：把「错」和「偏好」分开

交付物是校閲報告・指摘表・纳品用 Excel 的时候，**找到什么，和往表里放什么，是两件事**。

判据只有一个：**不改会怎样？**

| 档 | 不改的后果 | 去处 |
|---|---|---|
| 誤り | 读者会误解、事实对不上、日语不成立、一眼看出是外国人写的 | 主表，给重要度（高／中） |
| 要確認 | 判断不了对错，因为信息不在手上：实机 UI 文言、业务规则、客户既定术语 | 主表，但写成提问，不给断言式修正案 |
| 好み | 谁都不受损。只是「另一种说法也常见」「我会这么写」 | **不进主表**。要么不写，要么单列「参考（修正不要）」栏 |

一条自检立刻见效：**如果理由栏里写得出「誤りではないが」「〜のままでも可」「より一般的です」，那它当场就不是指摘。** 挪到参考栏，或者删掉。

实测里出现过这一例：`設定ガイド` 和 `カスタマーサービス` 被写进指摘表，理由分别是「セットアップウィザードのほうが一般的」「カスタマーサポートのほうが一般的」——而同一行的说明里已经写着「意味は通るためそのままでも可」「誤りではないが」。判断是对的，位置放错了。

为什么收得这么紧：**漏改是能力问题，误报是可信度问题，后者贵得多。** 客户翻开 5 行指摘表，发现 2 行是「换个说法也行」，剩下 3 行真问题的分量会跟着一起打折——他没有办法分辨哪几行该信。报告书本身就是收费交付物的时候，这张表干不干净就是交付质量本身。

拿不准算不算错的时候，**降级，不是删除**。放参考栏、标明「修正不要」。判断可以不准，位置不能放错。

| 优化 | 優化不是日语 | 最適化、改善 |
| 完善（动词） | 完善不作动词用 | 整備する、充実させる |
| 落实 | 不是日语 | 徹底する、実行に移す |
| 安排 | 不是日语 | 手配、段取り、調整 |

| 接口（系统间） | 接口＝管口・接头，不指 API | API、連携部分、インターフェース（API 最常用） |

### A-3 不是陷阱（不要过度矫正）

対応、確認、案件、実施、把握、措置、現場、架電、受電、入電、折返し——这些是地道日语（后四个是呼叫中心行话），照用即可。

注意「地道但别用错槽位」：検収是地道日语，但专指对**交付物**的验收（納品物の受入検査）；「实机验收通过」要写「実機検証に合格」，不是「実機で検収」。

## 表 C：中式句法与标点

- 名词长定语链（「AI完了偽装防止機構」式堆叠）→ 拆句，或用「〜するための〜」。
- 「〜を実施／進行／展開する」官腔 → 用具体动词：行う、進める、始める。
- 四字格对仗（安全可靠、高效稳定）→ 日语不追求对仗，选一个准确的词。
- 一逗到底的长句 → 一句一义，多用句号。
- 中文标点残留（，；：""《》）→ 日语标点（、。「」『』）；冒号只用于引导列表，不进句子。
- 「本次／该」→ 今回の、この。
- 量词直搬（2 周連続、三本场景）→ 按日语习惯：2 回通し、シナリオ 3 本。

以上是常见型，不是全部。通用判据：一句话只承担一个信息点，且断句位置是日本人会断的地方。

## 表外词怎么判

表外词**默认可疑，不默认安全**。「表里没有」不是放行理由。

### 六类成因（产生规则）

汉语词踩雷不是随机的，成因就这几条。对每个想直接照搬的汉字词问一遍：属不属于其中之一？

| 成因 | 特征 | 例 |
|---|---|---|
| ① 日语里是低频语・专门语 | 词存在，但日本同行文档日常用片假名或和语词 | 优化→最適化、维护→保守、界面→画面 |
| ② 词性不同 | 中文能作动词，日语只作名词・形容动词 | 完善する×、落实する× |
| ③ 近三十年新造词 | 中文互联网・管理学词汇，日语走了片假名路线 | 对接→連携、赋能→活用促進 |
| ④ 比喻义扩张 | 日语保留字面义・专业义，中文扩张成比喻 | 口径、抓手、主演、司令塔 |
| ⑤ 简称・缩略差异 | 中文的简称在日语里是别的词或不存在 | 单位→組織、总机→受付 |
| ⑥ 生造后缀 | 〜化・〜性・〜度・〜类 堆在不搭的词根上 | 场景化、可视化程度 |

命中任何一条 → 走下面的三级处置。六条都不像、且该词在日本同行文档里眼熟 → 可以用。

### 三级处置

1. **有把握**：知道原生说法（表内有，或凭确切见闻），直接换。
2. **拿不准**：有 WebSearch 就检索**实际用例**（企业网站、业界文章、公开的同类文档），搜不到实际用例即不用。这里要区分两个问题——「这个词存在吗」和「这个语境下日本人真的这么用吗」。只有后者算证据，自己的语感不算。
3. **无法检索**：退到朴素通名（一覧、履歴、台帳、画面、担当、対応），交付时明示「未検証」。通名不出彩，但永远不会错。

### 命名特则

给**产品・工具・页面・文档标题・固定栏目**起日语名风险最高：这类词会被反复引用，错了改起来最贵，而且「真词假搭配」正好落在这里——词典里有、句子里能用，但该语境下日本人不这么搭配。

实例：「司令塔」形容人和职能是高频原生日语，但没有日本人把工具或页面命名为「○○司令塔」；工具名的原生选择是 ダッシュボード・コックピット・コントロールタワー 这类片假名或通名。

- 命名一律按处置第 2 级以上：要么有实际用例，要么退到通名。
- 汉字比喻词（○○塔・○○艦・○○局・○○脳）作命名默认回避。

### 反向防线（别过度矫正）

产生规则容易让人疑心过重。判据始终是「日本同行会不会这么写」，不是「这个词长得像汉语所以危险」。见表 A-3：対応、確認、案件、実施、把握、措置、現場 都是地道日语，照用。

### 表外判定要留痕

交付时附一份「今回判定した表外語」（词 → 采用的写法 → 依据：用例/通名回退/未検証），三五行即可。这是三张表的增补来源，也让用户能复核我没证据就下的判断。

## 文体与语域

| 场景 | 文体 |
|---|---|
| 客户・营业方向 | です・ます体；お客様、ご確認、ご提案等美化语；结论先行 |
| 内部规格・清单 | だ・である体或体言止め；术语可保留英文 |
| 邮件 | です・ます体＋定型寒暄（お世話になっております等） |

- **用户指定文体时按指定的做，但先说一句惯行是什么。** 有些文书的文体是有惯例的：契約書・規程・仕様書＝である体＋「〜するものとする」；顧客向け案内・メール＝です・ます体。用户要求换成非惯行的文体（「合同太生硬，全改成敬体」）时，照做，同时用一句话说明「この種の文書は通常である体です。敬体版は確認・送付用として、正式締結版は法務確認を推奨します」。**说完照做，不替用户决定**——文体是用户的选择，风险提示是我的义务。
- 对外文档出现内部管理编号时必须带一句人话说明（例：管理番号 AI-30＝通話フローへの本人確認組み込み）。
- 敬语拿不准时降级用丁寧語，不硬上尊敬语・谦让语——用错比不用更刺眼。
- 片假名外来语取舍以日本同行业文档的高频写法为准，不自创。
- 表格单元格优先体言止め（「予備録画の準備」而非「予備録画を準備する」），比整句更像日本人写的表。

## Verification

**速訳**只做两项，合起来应该在一分钟内：

1. 数结构：两版的 `##` 数量、表格行数逐一相等。目视数一遍即可，**不要**为此跑脚本或反复调用工具。
2. 扫一眼有没有漏掉的表 A-1／表 B 词和中文标点。

速訳的验证到此为止。想再多做，说明档定错了——回去按清書做。

**清書**按这个顺序，第 1 项权重最大：

1. **「？」打点通读**：以「第一次看这份文档、不认识我们项目的日本人」身份从头读一遍，按七个卡点打点。**打点不为 0 即不合格**，无论词汇检查做得多干净。这一步不能用「我查过表了」代替——两者查的不是同一种病。
2. **反向对照（抓编造）**：拿日语成稿逐句回读中文原文，方向是**从日语找回中文**，专找「日语里有、中文里没有」的信息——多出来的限定语、修饰语、因果连接词、具体化的名词。找到就删回原文的粒度，或改成（要確認）。
   这一步和第 1 步方向相反，必须单独做：第 1 步在补信息，天然会补过头；靠同一遍通读自查抓不住自己刚加的词。**不要在这一步问「合理吗」，只问「原文里有吗」**——编造出来的东西通常都很合理，这正是它危险的地方。
   反过来也要防：这一步删的是**原文里没出处的信息**，不是删说明。第 1 步补的内部编号说明、缩写全称，只要内容能在原文里找到出处就留着，别在这一步一并砍掉。
3. **範囲の照合**：按「语义范围不许动」那张表逐项回对原文。这一步和第 2 步不一样——第 2 步找的是多出来的**信息**，这一步找的是被悄悄改宽或改窄的**范围**，后者不增一个字也能发生（超える→以上、かつ→または、含糊的指代被具体化）。改写、精简、换文体的任务必做，一项都不能跳。
4. 朗读测试：卡壳、拗口处即直译残留——回到工作流程第 2 步重写整段，不做词级修补。
5. 抽查：随机取 3 句问「日本の会社員が最初から日本語で書いた文書として違和感がないか」，有违和感即重写该段。
6. 数结构：花的精力应该接近零。
7. 过一遍「今回判定した表外語」清单：每一条要么有用例，要么是通名，要么标了未検証。三者都不是的，就是拿语感当证据——回到三级处置重判。
